# Afuza Ecosystem Registry (AX-02)

The portfolio discovery snapshots live under `.afuzactl/ecosystem/`. They describe evidence available from the mounted host at the last AX-02 discovery pass; they are not product PRDs and do not authorize implementation.

## Files

- `ecosystem.yaml` defines the portfolio identity, inspected roots, data files, and discovery-only execution policy.
- `projects.json` lists local projects/workstreams and named projects whose sources are external or unknown.
- `source-inventory.json` classifies PRDs, architecture, plans, workflows, implementation, and external references. Business-policy conflicts remain explicit.
- `requirements.json` contains only source-grounded normalized requirement candidates. Empty or partial project coverage is intentional when evidence or acceptance criteria are insufficient.
- `capabilities.json` maps candidate shared capabilities, likely providers/consumers, duplication risk, and uncertain ownership. It proposes no refactor.
- `dependencies.json` records project, capability, requirement, and planning-item edges, plus validated cycle, orphan, and unowned-capability summaries.
- `readiness.json` explains project readiness across product source quality, acceptance, dependencies, environment, testability, evidence, permissions, and external-source requirements.
- `execution-queue.json` is planning data only. AX-03 owns execution ordering.
- `schemas/` contains JSON Schema contracts. `./afuza doctor` validates schemas, unique IDs, cross-references, dependency cycles, readiness, and summary consistency.
- `report.md` is generated by `./afuza ecosystem report`.

## Authority And Uncertainty

Current code and tests establish implementation evidence, not business approval. An accepted ADR or explicitly locked product contract may be authoritative within its scope. Candidate, supporting, stale, conflicting, and unknown sources remain distinct; do not silently promote implementation behavior into product policy.

Google Drive is not mounted in this environment. Portfolio project entries flagged `external_source_required` are not claims that no PRD exists; their authority and currentness remain unknown until external references become available. Named business lines with no local sources are registered with unknown lifecycle, repository, domain, and dependencies.

AX-02X represents Drive documents directly in `source-inventory.json` with `source_type`, `external_document_id`, `document_title`, `version`, `authority_classification`, `last_known_metadata`, and `reconciliation_status`. A null document ID means a title reference is known but the ID was not supplied. Supplied IDs alone do not prove document contents were inspected. `contents_copied_to_repository` is always false. The authorized reconciliation artifact has now reconciled 11 source records across CHALWA.id, KlodHost, and Marketing Agency; only normalized evidence was imported, not document bodies. Thirteen other registered document records remain unreconciled locally. Those three projects are `EXECUTION_SPEC_READY` while repository/runtime, environment, dependencies, staging, and ownership checks remain open. PASOK.IN remains source-required because inspected folders were empty; HIKSAS and KonsultanHalal remain unresolved because no authoritative references were identified.

Both `EXECUTION_SPEC_READY` and `AUTONOMOUS_BUILD_READY` are evidence-gated, not document-count labels. `EXECUTION_SPEC_READY` requires an authoritative complete specification, business acceptance criteria, architecture, implementation sequencing, and a defined or passing verification strategy. It does not imply that the repository, runtime, dependencies, environment, staging path, or permission policy are ready. `AUTONOMOUS_BUILD_READY` additionally requires verified repository/runtime and environment, resolved dependencies, an available staging path, no blocking ownership conflict, a ready permission policy, and no outstanding external-source needs or blockers. A PRD/architecture/plan title alone cannot satisfy these gates.

The LP100/acquisition material contains conflicting scoring weights/thresholds and differences between human review, approval, draft creation, and actual message sending. The current non-executing approval guard is recorded as implementation evidence only. These are business decisions for a later approved specification, not AX-02 resolutions.

## Readiness

`EXECUTION_SPEC_READY` requires `authoritative_specification_available`, `acceptance_criteria_complete`, `architecture_available`, `implementation_sequence_available`, and testability of `STRATEGY_DEFINED` or `TESTED`, backed by a strong, complete source of truth. `AUTONOMOUS_BUILD_READY` additionally requires `repository_runtime_verified`, `environment_ready`, `dependencies_resolved`, `staging_path_available`, `ownership_conflict_status: NONE`, and `permission_policy_ready`; unknown or missing information blocks this classification. `PRD_MISSING_EXTERNAL` means the local corpus lacks the source and explicitly identifies an external source to retrieve; it does not mean no PRD exists.

The registry currently includes portfolio candidates named in AX-02 plus discoverable local projects and workstreams. Run `./afuza ecosystem discover` to identify new local directories. Review `UNCLASSIFIED` roots before registering them. Do not scan `.env` values, dependency/build directories, caches, or irrelevant backups.

## Commands

```sh
./afuza ecosystem status
./afuza ecosystem discover
./afuza ecosystem sources
./afuza ecosystem capabilities
./afuza ecosystem dependencies
./afuza ecosystem readiness
./afuza ecosystem report
```

These commands are read-only except `report`, which writes a generated report under `.afuzactl/ecosystem/`. No product feature work, production action, or external communication is performed by AX-02.
